SSH

Encryption and login happen in this tab. The relay only passes encrypted bytes along; nothing is sent to GitHub.

Server

As seen from the relay: the server's public address with the Cloudflare Worker, or localhost when bridge.py runs on the server itself.

Login

RSA or ECDSA keys in PKCS#8 format (passphrase-protected is fine). Convert a copy of an existing key with ssh-keygen -p -m PKCS8 -f copy_of_key. Ed25519 keys are not supported.

The server's questions (password, one-time code…) will be asked one by one.

Relay
How do I set up the relay?

Browsers (Safari included) can't open SSH connections themselves, so the encrypted SSH traffic goes through a small relay. It never sees your password, key or session. Pick one:

A. Cloudflare Worker (nothing to run anywhere)

Needs your SSH server reachable from the internet. Doable entirely from Safari.

  1. Tap . It fills in the Token field and copies it.
  2. In the Cloudflare dashboard (free account): Workers & Pages → Create → Worker → name it, Deploy → Edit code. Replace everything with worker.js and Deploy.
  3. Worker → Settings → Variables and Secrets: add a Secret TOKEN (paste the token) and a text variable ALLOW with your server, e.g. myserver.example.com:22.
  4. Put the Worker's address (https://….workers.dev) in Relay address, tick "Remember", connect.

B. bridge.py on the server

Works even if the server isn't reachable from the internet.

On that computer, download bridge.py and run python3 bridge.py --tunnel (uses a free cloudflared tunnel). It prints a link that fills in the address and token. It only reaches that computer's own SSH (localhost:22) unless you add --allow host:22.
